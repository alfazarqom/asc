6. KEAMANAN PEMBAYARAN

Terapkan aturan berikut:

Simpan kredensial Duitku di Supabase Secrets atau pengelolaan secret server yang sesuai.

Jangan menyimpan merchant key atau secret pembayaran di source code frontend.

Jangan menggunakan variabel VITE_* untuk kredensial rahasia.

Jangan mempercayai harga, diskon, ongkos kirim, atau total dari browser.

Hitung total transaksi berdasarkan data produk dan aturan harga yang tervalidasi di server.

Validasi kepemilikan pesanan dan hak akses pengguna.

Validasi callback dan signature sesuai dokumentasi resmi Duitku.

Terapkan idempotensi agar callback berulang tidak menggandakan perubahan transaksi.

Gunakan transaksi database atau mekanisme konsistensi yang sesuai saat memperbarui pesanan dan pembayaran.

Jangan pernah menandai pesanan lunas hanya karena pengguna kembali ke halaman sukses.

Jangan mencatat API key, merchant key, token, atau data sensitif ke log.

Batasi akses service-role dan gunakan hanya di lingkungan backend yang terpercaya.

Terapkan validasi jumlah, format, status, dan identitas transaksi.

Tangani callback yang tidak valid, transaksi kedaluwarsa, pembayaran gagal, dan request berulang.

Pastikan status pembayaran tidak dapat berubah kembali dari sukses menjadi pending atau gagal tanpa aturan bisnis yang sah.

8. KONTRAK PEMBAYARAN

Rancang alur berikut dan sesuaikan dengan format API yang telah diverifikasi.

A. Membuat pembayaran

Frontend mengirim identitas pesanan kepada create-duitku-payment.

Backend:

Memvalidasi identitas pengguna.

Membaca pesanan dan item dari database.

Memvalidasi status pesanan, harga, stok, dan total.

Membuat referensi transaksi yang unik.

Mengirim request ke Duitku sandbox.

Memverifikasi respons dan menyimpan referensi transaksi.

Mengembalikan hanya data yang diperlukan frontend.

B. Callback

duitku-callback:

Membaca payload sesuai format resmi Duitku.

Memvalidasi signature dan identitas transaksi.

Mencocokkan merchant order ID, nominal, dan referensi transaksi.

Memproses event secara idempoten.

Memperbarui status pembayaran dan pesanan sesuai aturan bisnis.

Mengembalikan respons callback yang diwajibkan dokumentasi.

C. Pemeriksaan status

check-payment-status:

Memvalidasi autentikasi dan kepemilikan pesanan.

Mengembalikan status yang tersimpan atau melakukan verifikasi server-to-server bila diperlukan.

Tidak mengizinkan frontend menentukan sendiri status lunas.

Jangan mengarang nama parameter, response field, signature formula, atau HTTP response callback. Cocokkan seluruh detail dengan dokumentasi resmi.
